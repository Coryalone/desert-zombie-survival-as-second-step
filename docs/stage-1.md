# Этап 1: первый бой

Flutter + Flame 1.38.2. 2D-графика с перспективной проекцией. Коллизии и игровой цикл обслуживает Flame; симуляция идёт маленькими фиксированными шагами.

Реализовано: один двухминутный тестовый заезд, три бойца / 30 HP, обычные зомби, автострельба, потери, пауза, повтор. Модель 10 HP на бойца и 6 урона за контакт — временная настройка для теста, не окончательный баланс. Пропущенный сбоку враг не наносит урона. Боковые съезды пока только изображены; бокового спавна нет.

Не реализовано: бонусы, элитки, боссы, техника, пять уровней, сохранения и аудио. Перезапуск приложения начинает новый бой.

## Запуск на Windows

Из корня проекта запустить Run-Web.cmd. Скрипт сам создаёт Android/Web-обвязку установленным Flutter и скачивает зависимости. Никакого нового движка отдельно устанавливать не нужно. Для Android: Build-APK.cmd, результат build/app/outputs/flutter-apk/app-release.apk.

Android/Web-обвязка генерируется в локальные игнорируемые каталоги. Источником Android-манифеста служит tool/android; изменения непосредственно в генерируемом манифесте будут заменены при prepare. Остальные существующие платформенные файлы не перезаписываются. На Windows путь проекта должен быть без кириллицы для Android Gradle.

APK предназначен для личного тестирования: стандартный Flutter-шаблон использует debug signing для release. Ключ на другом компьютере/CI будет другим, обновление поверх ранее установленной сборки может не пройти. Для стабильных обновлений следующим этапом нужен отдельный постоянный локальный ключ, который никогда не коммитится.

## Управление

Мышь: удерживать левую кнопку на поле и вести горизонтально. Палец: удерживать и вести. Дополнительно A/D или стрелки. Пробел/Escape — пауза. На экране есть кнопки паузы и повтора. Первый экран сразу игровой.

## Проверки

CI: генерация платформ, анализ Dart, тесты порогов HP/таймера/паузы и настоящих коллизий Flame, Web release, APK release, разрешения готового APK (допустимо только внутреннее signature-разрешение AndroidX), отключённый backup. Это не заменяет ручную проверку на телефоне.

Ручная приёмка: движение без скачка при нажатии; край дороги; быстрый и медленный жест; попадания; уменьшение бойцов; пауза и фон без продолжения боя; проигрыш и перезапуск; два размера экрана. Перед приёмкой этапа нужно проверить актуальный статус CI и эти сценарии.
